Braess Paradox Validation

Generated by py-osrm traffic assignment module

Structural validation of the density-based traffic assignment using the Braess paradox — a 4-node diamond network where adding a shortcut link increases total system travel time under user equilibrium.

Demand: 2,500 vehicles. 100 iterations per scenario. VDF: bi-parabolic speed-density (Fournier et al.), kc = kj/3. Methods compared: MSA (α = 1/n) and Frank-Wolfe (Beckmann line search).

Network Topology

The Braess diamond network (to scale): ● Origin (node 1), ● Destination (node 2). Red = narrow (1-lane, 60 km/h — congestion-sensitive). Blue = wide (3-lane, 40 km/h — high capacity). Orange = shortcut (1-lane, 60 km/h). Arterials are ~4 km; the shortcut is ~2 km (80 km/h).

TSTT Convergence

Red = network WITH shortcut, blue = WITHOUT. TSTT with shortcut = 2,169,893 veh·s (gap=0.000000), without = 1,883,294 veh·s (gap=0.000023). Δ = +286,599 (+15.2%). Braess paradox confirmed: adding the shortcut increases total travel time.

Convergence: MSA vs Frank-Wolfe

MSA (dashed envelopes, faint dots) vs Frank-Wolfe (solid lines). FW uses Beckmann line search to find the optimal step size each iteration, eliminating the bang-bang oscillation inherent to MSA on small networks. FW final gap: with shortcut = 0.000000, without = 0.000000.

FW Step Size

Optimal step size α* from the Beckmann line search each iteration. Dotted grey = MSA fixed schedule (1/n). Early iterations take large steps; as equilibrium is approached, FW takes progressively smaller steps — unlike MSA which follows a rigid 1/n schedule regardless of the objective landscape.
